# How to reproduce my entry

> **Template.** Replace every part of this file as your project changes. The staff replicate
> every entry from this file and `reproduce.sh` alone (see docs/POLICIES.md, "Documentation and
> end-to-end replication"). As shipped, both describe the baseline.

## Summary

- **Entry:** release `entry-…`, commit `…`
- **Approach in two sentences:** a small residual CNN (314K parameters) that imitates the move
  full-board Stockfish would play, from what the agent can see plus a memory of enemy pieces
  last seen. No search.
- **One command:** `bash reproduce.sh`

## 1. Environment

- Python 3.11, then `pip install -e ".[baseline]"`.
- Exact versions used: list them here, or commit `pip freeze > requirements-lock.txt` and say so.
- Stockfish 16: `bash scripts/get_stockfish.sh`, then `export STOCKFISH=…`.
- On Sol: `bash scripts/sol/setup_env.sh` once.

## 2. Data

| Step | Command | Output | Time and hardware |
|---|---|---|---|
| Games between reference bots, labelled by full-board Stockfish (5,000 nodes) | `python baselines/imitation/generate_data.py --games 4000 --workers 2 --out data/imitation --seed 0` | about 83,000 positions in `data/imitation/` | about 30 min, 2 CPU cores |

- **Sources:** all data is generated by the code above; nothing is downloaded.

## 3. Training

| Stage | Command | Seed | Time and hardware |
|---|---|---|---|
| Imitation | `python baselines/imitation/train.py --data data/imitation --agent-dir submission --epochs 8 --seed 0` | 0 | about 12 min, CPU |

## 4. Building `submission/`

`train.py` writes `submission/config.json` and `submission/weights/model.safetensors`. The code
in `submission/` (`agent.py`, `features.py`, `model.py`) is committed as is.

## 5. Expected results

- `python -m fow.validate submission` prints VALID, with 314,057 parameters and about 4×10⁷ FLOPs per move.
- Validation match with the teacher: about 39%.
- Local rating about 1200 on the course scale
  (`python -m fow.arena submission bot:greedy bot:guess-sf-4x500 --games 100`).

## 6. Compute used in total

About 1 CPU core-hour for data and 0.4 CPU-hours for training. The whole pipeline must run in
hours, not days.

## 7. Known sources of variation

- **Data:** different `--workers` values split the games differently, so the data differs slightly.
- **Training:** results vary by a few percent with hardware.
- **Rating:** expected to stay within the replication tolerance.
